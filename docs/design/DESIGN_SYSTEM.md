Create or update `docs/design/DESIGN_SYSTEM.md`.

Inspect existing UI components, Tailwind configuration, fonts, shadcn/ui setup, icons, and any existing design references.

Define a coherent, premium SaaS design system suitable for a professional company operations and infrastructure platform.

Include:

1. Design principles: clarity, consistency, information density, trust, usability, and restrained visual effects.
2. Brand direction and visual hierarchy.
3. Color tokens for backgrounds, surfaces, text, borders, primary actions, status indicators, and charts.
4. Light and dark themes with accessible contrast.
5. Typography, font sizes, line heights, weights, and text hierarchy.
6. Spacing scale, content widths, grids, breakpoints, and responsive rules.
7. Buttons, inputs, selects, checkboxes, dialogs, drawers, tooltips, tabs, cards, tables, badges, and navigation.
8. Sidebar, header, breadcrumbs, page titles, action areas, and dashboard layouts.
9. Form validation, loading indicators, skeletons, empty states, errors, confirmations, and toast messages.
10. Charts, status indicators, filters, search, pagination, and bulk actions.
11. Motion principles, durations, easing, reduced-motion behavior, and performance limits.
12. Accessibility requirements aligned with WCAG 2.2 AA.
13. Component reuse, naming, design-token conventions, and rules for extending shadcn/ui.
14. Examples of consistent patterns and anti-patterns.

Prefer a distinctive, polished interface over a generic template. Avoid excessive gradients, unnecessary animation, clutter, inconsistent radii, and decorative elements that reduce usability.

Base recommendations on verified existing configuration where possible. Clearly label proposed tokens that are not yet implemented.

Do not change the actual UI or install packages during this documentation task.
