Create or update `docs/design/SCREEN_INVENTORY.md`.

Inspect the actual Next.js routing structure and existing pages. Build an inventory that distinguishes existing routes from proposed routes.

For each screen record:

- Screen ID and display name.
- Route or proposed route.
- Module and user purpose.
- Authorized roles.
- Primary actions.
- Key UI components.
- Required data and backend dependencies.
- Loading, empty, success, error, and permission-denied states.
- Responsive considerations and accessibility requirements.
- Security-sensitive operations.
- Current implementation status.
- Dependencies and acceptance criteria.

Organize the inventory into logical modules such as authentication, workspace, dashboard, CRM, staff, tasks, support, chat, infrastructure, domains, hosting, payments, HR, settings, audit, and integrations.

Put the AI website-builder screens in a separate future-phase section. Consider plan selection, project creation, generation, editing, preview, publishing, domains, deployments, billing, usage, and customer support.

Do not invent actual routes or mark planned screens as implemented. Use the repository's real route conventions when proposing new routes.

Keep this inventory actionable for implementing one screen family at a time.
